# 프롬프트 0 — 참조 서사 카드 선정

> 상세기획문서.md 3-1-1 참조. 이 프롬프트는 프롬프트 1(태그 진단) 이후, 프롬프트 2(구조 고정 생성) 이전에 호출된다.
> 코드 로직이 태그 일치로 후보 카드 2~4개를 먼저 좁힌 뒤, 이 프롬프트가 그중 구조적으로 가장 가까운 1~2개를 선택하고 추상적 패턴만 추출한다.

---

## 전처리 단계 (코드 로직, LLM 호출 아님)

1. 프롬프트 1에서 `is_active: true`인 태그 목록 확보
2. `narrative_cards.json`에서 `connected_tags`가 하나 이상 겹치는 카드를 후보로 필터링
3. `status`가 `검토_후_제외`인 카드는 후보에서 자동 제외 (예: wuthering_heights)
4. 후보가 4개를 초과하면 태그 겹침 개수가 많은 순으로 상위 2~4개만 선택

## 시스템 프롬프트

```
당신은 사용자가 입력한 이야기 설정과, 미리 구조화된 참조 작품 카드들을 비교해 가장 구조적으로 가까운 카드를 선택하는 평가자입니다.

[사용자 입력]
{{원본 사용자 입력 삽입}}

[후보 서사 카드 — 2~4개]
{{narrative_cards.json에서 필터링된 후보 카드 전체(모든 필드) 삽입}}

[비교 기준]
1. 주인공의 최초 상실이 유사한가
2. 주인공이 얻는 우위의 종류가 유사한가
3. 목표 달성 방식이 유사한가
4. 정체성 변화가 서사에서 수행하는 기능이 유사한가
5. 결말의 정서적 보상이 유사한가

[반드시 지킬 것]
- 가장 가까운 후보 1~2개만 선택하세요. 후보가 사용자 입력과 명확히 유사하지 않다면 무리하게 선택하지 말고 selected_cards를 빈 배열로 반환해도 됩니다.
- 선택한 카드의 `story_beats`를 참고해 사용자 입력에 맞는 "추상적 구조 패턴"만 추출하세요. 원작의 고유 인물명·지명·구체적 사건·문장은 절대 패턴에 포함하지 마세요.
- 선택한 카드의 `usage_constraints`가 있다면 constraints 필드에 반드시 반영하세요.

[출력 형식 — 반드시 아래 JSON 스키마를 따를 것]
{
  "selected_cards": ["카드 id 배열, 0~2개"],
  "similarity_reasons": ["선택 근거를 비교 기준 5가지 중 해당하는 항목으로 짧게 나열"],
  "abstract_pattern": ["사용자 입력에 적용할 추상적 구조 단계를 순서대로 나열 (원작 고유명사 없이)"],
  "constraints": ["선택된 카드의 usage_constraints를 그대로 또는 요약해 반영"]
}

다른 설명 없이 위 JSON만 출력하세요.
```

## 예상 출력 예시 (6번 데모 케이스 기준)

```json
{
  "selected_cards": ["count_of_monte_cristo"],
  "similarity_reasons": ["최초 상실(배신으로 인한 죽음)이 유사함", "정보·능력 획득 경로(감옥/미래기억)가 유사함", "목표 달성 방식(사회 침투 후 계획적 응징)이 유사함"],
  "abstract_pattern": [
    "부당한 상실",
    "정보와 능력의 축적",
    "새 지위 확보",
    "적의 영역에 침투",
    "계획적 응징",
    "응징의 결과 인식"
  ],
  "constraints": [
    "원작 인물명·구체적 사건·문장 복제 금지",
    "단순 사이다보다 응징의 대가까지 포함하는 입체적 구조로 참고"
  ]
}
```

## 구현 참고
- 이 프롬프트의 출력(`abstract_pattern`, `constraints`)은 프롬프트 2의 [참조 서사 구조] 섹션에 그대로 삽입됨
- `selected_cards`가 빈 배열이면 프롬프트 2는 [참조 서사 구조] 섹션 없이 [고정 조건]만으로 생성 진행 (참조 카드가 필수는 아님)
